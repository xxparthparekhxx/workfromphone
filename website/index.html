Linux Service & Flutter Client Architecture

A remote Linux dev environment that lives in your pocket.

WorkFromPhone pairs a native mobile client with an isolated Linux daemon: persistent PTY subshells, live hardware telemetry, sandboxed file editing, Git workspace sync, dev-server preview proxying, and an autonomous LLM coding loop — all from a phone.

Subsystem Architecture & Capabilities

01 · PTY Subsystem fcntl / openpty / termios

Persistent Linux PTY Sessions

Manages bidirectional pseudo-terminal sessions over authenticated WebSockets. Features non-blocking I/O, xterm ANSI color stream framing, window resizing (cols/rows), process group tracking with clean SIGKILL teardown, and sanitization of environment secrets on subshell spawn.

02 · Telemetry /proc & sysfs / WebSockets

Hardware Metrics Engine

Streams live sub-second system performance snapshots. Collects per-core CPU utilization, memory/swap allocations, disk I/O throughput and partition metrics, top resource-consuming processes, zone thermals, and NVIDIA/AMD GPU statistics without leaking process arguments.

03 · Autonomous Loop OpenAI API / SSE / tool calls

LLM Agentic Coding Harness

Autonomous execution loop that communicates with OpenAI or OpenRouter models. Built-in tool calling inventory executes terminal bash commands, reads file line slices, performs exact substring replacements, executes project tree searches, and registers web dev preview targets.

04 · Filesystem pathlib / multipart / spooling

Sandboxed File Operations

Strict path canonicalization prevents directory traversal attacks outside designated project roots. Binary-safe chunked multipart uploads stream into temporary spool files, validate maximum payload size constraints, and atomically swap destination files.

05 · Version Control Git CLI / unified diffs

Git Workspace Subsystem

Native Git CLI wrapper exposing repository status, staged/unstaged unified diffs, selective staging (git add), unstaging (git restore --staged), discard operations, commit creation, branch listing, and remote upstream push/pull synchronization.

06 · Reverse Proxy httpx / SPA rewrites / SSRF check

In-App Dev Server Web Preview

Reverse-proxies active local web development servers (Vite, Next.js, Flask, Flutter Web) directly to the client webview. Implements loopback port whitelist enforcement (1024-65535), SSRF validation against cloud metadata IPs, and sensitive header stripping.

Setup & Configuration Guide

Run this single command on your remote Linux host. It handles architecture detection, SHA-256 validation, access token generation, and systemd service installation.

bash (remote server) 
curl -fsSL https://raw.githubusercontent.com/xxparthparekhxx/workfromphone/master/scripts/install.sh | bash

Extract and run the self-contained binary manually in a terminal or tmux session.

bash (x86_64 example) 
# 1. Create installation directory
mkdir -p ~/.local/share/workfromphone/current

# 2. Download and unpack archive
curl -fsSL https://github.com/xxparthparekhxx/workfromphone/releases/download/backend-v0.1.0/workfromphone-backend-linux-x86_64.tar.gz \
  | tar -xz -C ~/.local/share/workfromphone/current

# 3. Restrict permissions and start service
chmod 700 ~/.local/share/workfromphone/current/workfromphone-backend
ACCESS_TOKEN="your-secure-access-token" PORT=8000 ~/.local/share/workfromphone/current/workfromphone-backend

Configure a user-level systemd daemon so the service automatically restarts on failure and starts on system boot.

bash (systemd unit configuration) 
# 1. Write environment configuration file
mkdir -p ~/.config/workfromphone ~/.config/systemd/user
cat <<'EOF' > ~/.config/workfromphone/backend.env
HOST=127.0.0.1
PORT=8000
ACCESS_TOKEN=your-random-token-here
DEBUG=false
EOF
chmod 600 ~/.config/workfromphone/backend.env

# 2. Create user systemd service file
cat <<'EOF' > ~/.config/systemd/user/workfromphone-backend.service
[Unit]
Description=WorkFromPhone Backend
After=network-online.target

[Service]
Type=simple
EnvironmentFile=%h/.config/workfromphone/backend.env
ExecStart=%h/.local/share/workfromphone/current/workfromphone-backend
Restart=on-failure
RestartSec=2

[Install]
WantedBy=default.target
EOF

# 3. Reload daemon and enable service
systemctl --user daemon-reload
systemctl --user enable --now workfromphone-backend.service

# 4. Verify status
systemctl --user status workfromphone-backend.service

Establish a secure outbound named tunnel using Cloudflare. Enables access without exposing ports through home or cloud firewalls.

bash (cloudflared daemon setup) 
# 1. Download cloudflared binary
mkdir -p ~/.local/bin ~/.config/workfromphone ~/.config/systemd/user
curl -fsSL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o ~/.local/bin/cloudflared
chmod 700 ~/.local/bin/cloudflared

# 2. Store tunnel credential token
cat <<'EOF' > ~/.config/workfromphone/cloudflared.env
CLOUDFLARE_TUNNEL_TOKEN=your-tunnel-token-string
EOF
chmod 600 ~/.config/workfromphone/cloudflared.env

# 3. Install systemd tunnel unit
cat <<'EOF' > ~/.config/systemd/user/workfromphone-tunnel.service
[Unit]
Description=WorkFromPhone Cloudflare Tunnel
After=network-online.target workfromphone-backend.service

[Service]
Type=simple
EnvironmentFile=%h/.config/workfromphone/cloudflared.env
ExecStart=%h/.local/bin/cloudflared tunnel --no-autoupdate run --token ${CLOUDFLARE_TUNNEL_TOKEN}
Restart=on-failure
RestartSec=3

[Install]
WantedBy=default.target
EOF

# 4. Enable and start tunnel
systemctl --user daemon-reload
systemctl --user enable --now workfromphone-tunnel.service

Build the Flutter mobile client configured with your release repository for automatic remote SSH host provisioning.

bash (client build) 
# Build release Android APK
flutter build apk --release --dart-define=WFP_BACKEND_RELEASE_REPO=xxparthparekhxx/workfromphone

# Or run directly on connected device
flutter run -d <device_id> --dart-define=WFP_BACKEND_RELEASE_REPO=xxparthparekhxx/workfromphone

HTTP & WebSocket Protocol Specification

All routes except /api/v1/health require a Bearer access token evaluated via constant-time string comparison (hmac.compare_digest).

Protocol Method Endpoint Path Auth Functional Description
HTTP GET /api/v1/health Public Service status and version check
HTTP GET /api/v1/system/snapshot Bearer Hardware snapshot (CPU, RAM, Disks, GPUs)
WS CONNECT /api/v1/system/ws Bearer Real-time sub-second hardware metric stream
WS CONNECT /api/v1/terminal/ws Bearer Interactive persistent PTY terminal session
HTTP GET /api/v1/fs/browse Bearer Sandboxed directory and file tree browsing
HTTP GET /api/v1/fs/file Bearer Read file text content with line slicing
HTTP POST /api/v1/fs/upload Bearer Chunked multipart binary file upload
HTTP GET /api/v1/git/diff Bearer Working tree and staged unified Git diffs
HTTP POST /api/v1/git/stage Bearer Stage modified file paths (git add)
HTTP POST /api/v1/llm/chat Bearer Autonomous agent task loop (SSE stream)
HTTP ANY /api/v1/preview/proxy/{id}/{path} Bearer Dev server reverse proxy with SSRF validation
